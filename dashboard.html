The Dashboard

The dashboard is a web page that lets you see every active terminal session, watch what someone is typing in real time, and cut off a session with one click — all from any browser, no app needed.

On this page

  1. Opening the dashboard
  2. Watching a live session
  3. Stopping a session
  4. Keyword alerts

// 01

Opening the dashboard

The dashboard is built into the same server the terminal connects to. Open any browser and go to your server's URL — no extra setup needed.

1

Go to your server URL

Open a browser and navigate to https://kali-terminal-production.up.railway.app (or your own server address).

2

Enter the dashboard password

You'll see a login screen. Enter the dashboard password — the default is set via the DASHBOARD_PASS environment variable on your server.

3

You're in

You'll see stats at the top (total sessions, active now, commands run, alerts) followed by the sessions table, command history, and any alerts.

ℹ

The dashboard auto-refreshes every 30 seconds. You can also hit ↺ Refresh in the top-right to reload immediately.

// 02

Watching a live session

Any session that is currently active has a ◉ Watch button in the Sessions table. Clicking it opens a live terminal window right inside your browser — you can see every keystroke and output as it happens.

Sessions 2 rows

a3f9c1 192.168.1.42 13 May 20:14 12 ● live
7bd22e 10.0.0.5 13 May 19:50 4 closed

Clicking ◉ Watch opens a live terminal window inside your browser:

LIVE VIEW — a3f9c1 ×
root@kali:~$ ls -la /etc
total 312
drwxr-xr-x 1 root root 4096 May 13 20:14 .
drwxr-xr-x 1 root root 4096 May 13 19:00 ..
root@kali:~$
✦

Live view is read-only — you can watch but not type. The terminal user won't know you're watching.

Close the live view by clicking the × in the top-right of the window, or by clicking anywhere outside it.

// 03

Stopping a session

Active sessions have a ■ Stop button next to the Watch button. Clicking it immediately closes the terminal connection — the user's shell is killed and the session is marked as ended in the database.

Sessions
IDIPStatus
a3f9c1 192.168.1.42 ● live
1

Click ■ Stop

A confirmation dialog will ask you to confirm — this prevents accidental disconnects.

2

Confirm

Click OK. The session is immediately terminated. The user will see their terminal connection drop.

3

Session moves to history

The session row updates to closed status. Its command history stays saved in the database.

⚠

Stopping a session is immediate and cannot be undone. Any unsaved work in that terminal will be lost.

// 04

Keyword alerts

The server watches every command for dangerous patterns. When one is detected — like rm -rf, nc -e, or chmod 777 — it creates an alert and shows a red banner at the top of the dashboard.

To dismiss all alerts at once, click ✓ Dismiss All in the alerts card header. Individual alerts can also be deleted from the list.

ℹ

Alerts are logged even after the session ends, so you can review them any time in the dashboard history.
